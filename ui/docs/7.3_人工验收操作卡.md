## B. 模拟器故障场景（使用 acceptance-samples/ 样本）

粘贴方法：打开开发者工具"调试基础库 → 本地设置/模拟器 → 调试器 Storage 面板"或在首页备份文本框粘贴。样本文件在 `acceptance-samples/`。

| # | 场景 | 操作 | 通过标准 | 结果/证据 |
|---|---|---|---|---|
| B1 | 有效 v1 本机数据迁移（P0-1） | Storage 面板删除 `labsafe.v1.snapshot.A`、`.B`、`.active` 三个键；新增键 `labsafe.v1.snapshot.A`＝`storage-key-A.txt` 全文，`labsafe.v1.snapshot.active`＝`storage-key-active.txt` 全文；重新编译 | 首页正常显示 4 设备/2 异常（不报 STORAGE_CORRUPT）；任意上报一次异常后，Storage 中被写入的槽 `schemaVersion` 变为 2；重启后新记录仍在 | |
| B2 | 坏校验包 | 首页文本框粘贴 `backup-bad-checksum.json` 全文 →"预检备份" | 提示校验值不匹配（BACKUP_CHECKSUM_MISMATCH），不出现"确认恢复"按钮；当前数据不变 | |
| B3 | 断裂引用但校验值正确的包（P0-2） | 粘贴 `backup-broken-ref.json` → 预检 | 提示备份无效（BACKUP_INVALID，消息含"巡检模板指向不存在的设备"）；不出现恢复按钮；首页计数不变 | |
| B4 | 超限包（P0-3） | 粘贴 `backup-oversize.json` → 预检 | 明确返回存储超限（STORAGE_LIMIT，约 901 KB > 900 KB），**不得**出现 canRestore:true 或恢复按钮——即"预检可恢复、恢复必失败"不再发生 | |
| B5 | 正常包往返 | 先 A2 上报几条数据 → A9 导出并另存；再用 `backup-good.json` 预检→确认恢复 | 预检给出各集合计数；恢复成功；重启后数据回到备份时刻（注意演示角色也会回到备份时的状态，属预期语义） | |
| B6 | 单槽无可信指针 | 在 B1 基础上删除 `labsafe.v1.snapshot.active` 键、只留 A 槽 → 重新编译 | 显式提示存储状态不确定（STORAGE_UNCERTAIN 文案），不静默重置数据；恢复指针键后恢复正常 | |
