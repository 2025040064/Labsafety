# 智维云改造：实施计划与审计

## 目标与边界

在现有微信小程序、Python HTTP 服务和 RAC-HPO 引擎上，优先完成可追溯的工业分类闭环；保留原有功能和数据。AI4I 2020 是公开合成数据，训练结果为离线实验，不是实时设备状态。首次使用前必须确认数据来源、字段、划分和实验指标。

## 实施顺序

1. 保存现有代码和未提交状态，核查架构、数据、数据库和测试基线。
2. 复用工业分类服务，补充可用数据集、数据预览、统计和后台任务进度所需接口；为修复先编写失败测试。
3. 在现有工作区增加智维云入口、真实统计、数据来源与分类任务流程，保留其他工作台功能。
4. 完善 CSV 接入、验证和记录；仅开放后端真实支持的能力。
5. 使用隔离数据工作区执行真实训练及接口测试，检查微信开发者工具，再更新运行和验收文档。

每阶段记录实际通过、失败和未验证项目；不自动提交、推送或发布。原始数据、数据库和已有实验不可删除或覆盖。

## 阶段 0：现状审计（进行中）

- Git 当前分支 `main`，存在大量用户未提交的修改、删除和未跟踪文件；不能用 HEAD 替代当前工作树。原 Labsafety 实验室安全页面和测试在工作树中已删除；当前小程序路由为单个 `pages/workspace/index`，其三个工作台入口覆盖训练、结果、历史等功能。
- 改造前代码与已跟踪差异已存入本目录的 ZIP，排除缓存与数据目录；ZIP 完整性检查通过。历史实验和数据库继续保留在原位置，不将它们当缓存删除。该备份不是数据库备份。
- `backend/server.py` 提供 HTTP、单个子进程任务、任务与事件 SQLite 存储、取消、结果与导出；`actions.py` 转发到应用服务，`views.py` 汇总/分页实验、试验和图表。任务创建返回 `JOB-*`，当前直接进入 `running`，已有任务重启标记为 `interrupted`，没有排队队列。
- 实际分类调用链：`POST /api/jobs` → `Workspace.start` → `worker` → `run_action(industrial_run)` → `IndustrialService.run` → `rac_hpo.optimization.classification.optimize` → `RACSearchPolicy`（仅 `rac_hpo` 方法）与分类训练器。代理门禁等机制存在于策略内，但单个实验是否启用应以具体运行记录为准；搜索需要预热，不能只凭选择 RAC-HPO 宣称代理已生效。
- 回归调用链：`run_action(optimize)` → `ApplicationService.run_experiment` → 优化入口及训练器。分类与回归分开存储和展示；分类搜索以验证集固定归一化目标为选择依据，不应称为测试集性能。
- 数据与引擎分离：`backend/engine/src/rac_hpo` 保存数据适配、训练、优化、评估及存储代码；`rac-data` 保存配置、公开原始数据、数据清单、上传和实验。AI4I 原始快照存在；NASA 等原始数据存在不代表可用于当前分类训练。具体数据许可见现有来源文档。
- SQLite 只读检查：`lab.sqlite3` 保存 jobs、job_events、members、tokens；`experiments.sqlite3` 保存回归实验与 trials；`lifecycle.sqlite3` 保存离线会话事件。工业分类结果保存在 `workspace/industrial_runs`，不是上述回归实验数据库。
- 当前支持工业数据审计、受适配器约束的文件导入、分类训练、搜索、结果、历史及导出；任意 CSV 字段映射和通用训练尚未实现。任务完成前的事件处理丢弃 `trial` 明细；需要验证并修复。现有云模式存在用户成员机制，但任务列表、详情与数据读取没有逐用户隔离，不能宣称多用户安全；当前目标以本机单用户为边界。
- 自动测试基线：系统默认 Python 缺少 pandas，16 项中 5 项报错；使用原项目现有 Python 3.11 环境，`python -m unittest discover -s backend/tests -p 'test_*.py'` 为 16/16 通过。测试包括动作参数转发、视图和任务重启等单元测试，不能代替真实训练及小程序验收。
- 微信开发者工具当前编译、真机访问、完整交互、真实分类和 RAC-HPO 高级机制：尚未验证。
